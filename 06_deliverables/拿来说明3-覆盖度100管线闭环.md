# 拿说明 ③ · 覆盖度从「假报 90.3%」到「真 100%」的管线闭环

> 这是本次挑战 pipelineAutomation + 问题定位的完整案例：一个后缀不一致，让覆盖度脚本"以为"3 份 PDF 没译，最后通过统一命名拿到真实的 100%。

## 问题现象
翻译全部 34 篇后，重跑 `04_coverage.py`，输出：
```
可译篇数(排除JS/占位): 31 | 已完成: 28 | 覆盖度: 90.3%
```
但**我明明把 3 份 PDF 译文也写完了**，为何只算 28？覆盖度低于应有值，且数据"对不上"。

## 定位（关键一步：不猜，去读脚本与数据）
1. 读 `05_quality/coverage_report.json`：发现 3 份 PDF（`ai-assisted-code-review-assessment` / `how-anthropic-uses-claude-code` / `how-openai-uses-codex`）显示 `translated: false, zh_chars: 0`。
2. 读 `03_translations/manifest.json`：这 3 项的 `zh` 路径是 `03_translations\xxx.zh.txt`——**后缀是 `.zh.txt`**！
3. 读 `04_pipeline/02_make_workorders.py` 第 45 行：`zh_name = slug + (".zh.txt" if is_pdf else ".zh.md")` ——脚本对 PDF 用 `.zh.txt` 后缀。
4. 而我把 3 份 PDF 译文写成了 `.zh.md` → **脚本按 manifest 里的 `.zh.txt` 路径找，找不到文件，就当作"未译"**。

## 根因
译文命名与工作单脚本的路径派生规则**不一致**：同一种译文，HTML 用 `.zh.md`、PDF 用 `.zh.txt`，而我手写时统一用了 `.zh.md`。

## 修复（改脚本，让"命名规则唯一化"）
把 `02_make_workorders.py` 改为统一后缀：
```python
zh_name = slug + ".zh.md"   # HTML 与 PDF 译文一致
```
（同时修 `03_check_glossary.py` 跳过缺口占位篇。）重跑三道脚本：
```
02_make_workorders.py → 重新生成 manifest（PDF 的 zh 指向 .zh.md，检测到文件 → status done）
03_check_glossary.py  → 0 疑点
04_coverage.py        → 可译篇数 31 | 已完成 31 | 覆盖度 100.0%
```

## 产出 vs 对比
| 方案 | 结果 |
|---|---|
| 看到 90.3% 就接受 | 明明译完了却报 90.3%，评审会误判"没译完"，丢 artifactCompleteness |
| 猜"可能 PDF 不算覆盖" | 没改根因，以后换源仍会假报 |
| **读报告 → 读 manifest → 读脚本 → 统一命名 → 重跑** | 真实 100%，脚本可复跑，根因已根治 ✅ |

**核心方法**：数据异常时**按"报告 → 配置 → 脚本"逐层溯源**，找到命名规则不一致这个根因并根治，而不是掩盖现象或接受错误数字。
