# 拿说明 ① · 术语表 79 条是怎么「哪个得分高用哪个」定稿的

> 这是本次挑战最关键的"人工决策 + AI 辅助"产出：79 条术语的译法统一，直接决定了 34 篇译文的质量地基。

## 问题
课程里有大量高频技术词，若不先统一，翻译时会"一词多译"——例如 **Agent** 可能被翻成"代理/智能体/自动体"，**Prompt Engineering** 可能翻成"提示工程/提示词工程/快速工程"。术语不统一是机器翻译最常见的质量杀手（对应评分维度 **contentAccuracy**）。

## 我（AI）做了什么
先通读 31 篇讲义 + 3 份 PDF，抽取高频技术词，起草术语表，按三类处理：
- **需中文化**：Agent→智能体、Prompt Engineering→提示词工程、Context rot→上下文腐化、MCP→模型上下文协议（MCP）；
- **需保留英文（专名）**：Claude Code / Warp / GitHub / Kubernetes / MCP 等，中文并列首次出现后保留英文；
- **产品名**：一律保留英文。

## 交给你的 prompt（决策点）
```
术语表已起草 79 条，其中两条有争议：
- Agent：译"智能体" vs "代理"？
- Prompt Engineering：译"提示词工程" vs "提示工程"？
你之前说"哪个得分高用哪个"，请据此拍板。
```
你回复：**哪个得分高用哪个**。

## 我的处理（把"得分高"翻译成可执行标准）
把"得分高"拆成三条硬标准，逐条套用：
1. **全文统一**（同词同译、可检索）；2. **准确无硬伤**（Agent 在 LLM 语境下是"自主完成任务的程序"，译"智能体"比"代理"语义更准）；3. **可读性**（Prompt Engineering 已是社区通行词，译"提示词工程"既准确又易懂）。
→ 据此定稿：**Agent→智能体、Prompt Engineering→提示词工程**，专名保留英文。

## 产出 vs 不这么做的对比
| 方案 | 结果 |
|---|---|
| 不统一，直接翻 | Agent 时而"代理"时而"智能体"，评审一眼看出不专业，contentAccuracy 丢分 |
| 我逐条定稿（未问你） | 可能与你偏好不符，返工 |
| **术语表先行 + 你拍板 + 三标准执行** | 79 条定稿后 34 篇全文统一，质量闸门 0 疑点，零返工 ✅ |

**核心方法**：把模糊的用户偏好（"得分高"）翻译成**可执行的硬标准**，再据此做决策，并把决策写进术语表留痕。
