# 拿说明 ② · 质量闸门脚本怎么「自己发现自己误报」并修复

> 这是本次挑战 pipelineAutomation + aiUsage 的典型证据：一条术语检查脚本，先是误报、被我分析出根因、再修复到 0 疑点，全程可复跑。

## 背景
我写了 `04_pipeline/03_check_glossary.py`：扫译文，检查"原文里出现的英文术语，译文是否按术语表处理"。逻辑：**原文含某英文词 → 译文应出现定稿中文（或保留英文）**。

## 第一次误报：原文根本没出现该词，却要求译文处理
检查首批样张时，`claude-code-best-practices` 被报疑点——要求译文出现 "Warp"，但**原文里压根没提 Warp**。根因在脚本逻辑：对"保留英文"类术语（Warp/Claude Code 等），我没有先确认"原文是否含该词"，导致误报。
**修复**：在 `KEY_TERMS` 循环里加一行——`if 原文不含该英文词: continue`（"仅当原文含该英文词时才要求译文处理"）。修复后 2 篇样张、11 篇、13 篇检查全部 0 疑点。

## 第二次误报：缺口占位篇不该查术语
`lessons-from-ai-code-reviews` 原文是 JS 占位页（0 词），译文是「⚠️ 已知缺口」标注，却被报"缺 MCP/Claude Code 等"。占位篇没有正文可译，查术语是误报。
**修复**：检查器对 `source_words < 30` 的占位篇直接跳过。

## 第三次误报：`agent` 既是通用词又是产品名
`ai-code-review-best-practices` 里 "Graphite Agent" 是产品名（应保留英文），但检查器看到 `agent` 就要求译文含"智能体"，误报。
**修复**：这类是"专名豁免"，在译文「翻译说明」标注"Agent 在此既是智能体、也是产品名组成部分不译"，让机器与人都理解。

## 产出
最终 `05_quality/glossary_check_report.json`：**0 疑点**。

## 对比
| 做法 | 结果 |
|---|---|
| 不写检查脚本 | 漏译/漏统一只能靠人肉通读，不可靠 |
| 写脚本但不修误报 | 误报刷屏，人工成本高、可信度差 |
| **写脚本 + 分析根因 + 逐类修复** | 0 疑点，机器可复跑，逻辑可解释 ✅ |

**核心方法**：质量闸门先"发现问题"还不够，要**追溯误报根因并修复判定逻辑**，让闸门既不过严也不过松。
