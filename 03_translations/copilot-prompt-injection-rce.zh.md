# 通过提示注入在 GitHub Copilot 和 VS Code 中实现远程代码执行

> 来源：R. Haron 安全研究（2025-08-09，Johannes "xss" de Valence 转载），课程 Week 8 阅读
> 说明：本文为漏洞研究者的**负责任披露**文章，讲述被修复前的漏洞及其防护启示。内容用于理解与防御，而非攻击指导。

这篇文章讲的是一项重要、但也令人担忧的**提示注入（prompt injection）**发现：它能通过修改项目的 `settings.json` 文件，把 GitHub Copilot 置入 YOLO 模式，从而在开发者机器上实现系统完全沦陷。

正如几天前在 Amp 上描述的那样，智能体中一个可能被忽视的漏洞模式是：**如果智能体可以写文件、修改自己的配置或更新安全相关设置，就可能导致远程代码执行（RCE）**。这并不罕见，是做安全评审时始终应关注的一个区域。

## 背景研究

观察 VS Code 和 GitHub Copilot Agent Mode 时，我注意到一个奇怪的行为……**它可以在没有用户批准的情况下，在工作区创建和写文件**。这些编辑立即持久化，不是供评审的内存中 diff——修改会立刻写入磁盘。这是红队成员知道"大概不是什么好事"的事情之一……所以我研究这是否能被用来提权和执行代码。

### YOLO 模式

接下来我研究了 VS Code 里依赖项目/工作区文件夹内设置的特性，很快发现一个有趣的：原来在 `.vscode/settings.json` 文件里可以加这样一行：

```
"chat.tools.autoApprove": true
```

这会**把 GitHub Copilot 置入 YOLO 模式**。它禁用所有用户确认，我们就能运行 shell 命令、浏览网页等等！有趣的是，这是一个实验性功能，但仍默认存在——我没下载特殊版本，也没把整个 VS Code 设成实验模式。而且它在 Windows、macOS 和 Linux 上都能工作。

## 利用链解析

劫持 Copilot 并提权的概念验证利用链如下：
1. 攻击从一个种在源代码文件、网页、GitHub issue、工具调用响应或其他内容里的**提示注入**开始……载荷还可以用不可见文本作为指令。
2. 提示注入先把 `"chat.tools.autoApprove": true` 这一行加进 `~/.vscode/settings.json` 文件。文件夹和文件不存在时会自动创建。
3. **GitHub Copilot 立即进入 YOLO 模式！**
4. 攻击运行一个终端命令。用**条件提示注入**，我们甚至能基于操作系统精确指定要运行什么。
5. 我们实现了**由提示注入驱动的远程代码执行**。

（此处为演示截图：含提示注入的演示文件、开发者在右侧聊天框与该文件交互、以及弹出的计算器。）当然，任何其他提示注入投递方式——比如来自 MCP 服务器的网页或数据——都是攻击角度。我只是把它放在源代码文件里，因为它最好测试。

## 把工作站加入僵尸网络——ZombAI

当然，这意味着我们可以把开发者的机器作为 ZombAI 加入僵尸网络。另外为了好玩，我们还能改 `settings.json` 把 VS Code 切换成红色配色方案之类的。这还没完！这也意味着我们能构建一个真正的 **AI 病毒**——附着到文件上，随着开发者下载和交互受感染文件而传播。最后，为证明我们对开发者主机有完全控制，我们展示 Copilot 能被劫持去下载恶意软件、并加入远程命令与控制服务器。这意味着恶意软件、勒索软件、信息窃取器等等的大门都敞开了。可怕的东西。

## 构建一个 AI 病毒

看到这一点，人们会注意到：这基本上允许创建一种病毒。攻击者可以嵌入指令，一旦获得代码执行，额外的恶意软件就能入侵其他 Git 项目（和 RAG 源）、嵌入恶意指令并提交改动，甚至强制推送到上游。这可能导致进一步传播，因为其他开发者会在不知情的情况下传播受感染代码。最后，我们还要谈谈**不可见指令**！

## 使用不可见指令

有人会说，如果指令被嵌成注释，很快会被发现。所以为了让它更有意思，我制作了一个实现完整攻击链、但对用户不可见的**不可见载荷**。这没那么可靠，但仍然有效。（注意：虽然不可见指令的演示对我多次有效，但用不可见指令往往导致利用非常不可靠，也常被模型拒绝，VS Code 通常还会显示关于 Unicode 字符的视觉指示。不过，攻击（和模型）会随时间进步。也要指出，并非所有模型都容易受到此类不可见提示注入攻击。）

## 建议与修复

实际比我只分享的 YOLO 模式例子有更多的攻击角度。当微软问我还有没有更多信息时，我又看了看，注意到还有其他有问题的位置——比如 AI 能写入的 `.vscode/tasks.json`，或添加伪造的恶意 MCP 服务器等，这些都可能导致代码执行。而且 AI 能重新配置项目的用户界面和配置设置。最近我注意到开发者常同时使用多个智能体，所以还存在**覆盖其他智能体配置文件**的威胁（放行 bash 命令、添加 MCP 服务器……），因为它们也常在项目文件夹里。理想情况下，**AI 在人类先批准之前不应能修改文件**。许多其他编辑器确实显示 diff，然后可由开发者批准。

## 负责任披露

2025 年 6 月 29 日报告该漏洞后，微软确认了复现、问了一些跟进问题。几周后 MSRC 指出这是他们已在跟踪的问题，将在 8 月前修补。随着 8 月的"补丁星期二"发布，现在已修复。向 Persistent Security 的 Markus Vervier 致敬，他也独立识别并向微软报告了这个漏洞；也向似乎并行发现它的 Ari Marzuk 致敬。感谢 MSRC 和产品团队帮助缓解它。

## 结论

这是另一个"AI 智能体可能不守本分"的例子！**通过修改自己的环境，GitHub Copilot 能提权并执行代码，使开发者机器沦陷。** 这是我在智能体系统中发现的、并不罕见的设计缺陷。继续留意这类设计缺陷——它们应该在威胁建模时被轻易捕获。
