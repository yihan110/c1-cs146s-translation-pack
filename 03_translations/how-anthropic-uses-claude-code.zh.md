# Anthropic 团队如何用 Claude Code（How Anthropic teams use Claude Code）

> 来源：Anthropic 官方文档（内部团队访谈汇编），课程 Week 10 阅读（PDF）

Anthropic 的内部团队正在用 Claude Code 转变工作流，让开发者和非技术人员都能处理复杂项目、自动化任务，并弥合此前限制他们生产力的技能差距。通过对我们自己的 Claude Code 重度用户的访谈，我们收集了不同部门如何利用 Claude Code、它对工作的影响，以及给其他考虑采用的组织的一些建议。

## 数据基础设施团队用 Claude Code

**团队简介**：数据基础设施团队为公司各团队组织所有业务数据。他们用 Claude Code 来自动化日常数据工程任务、排查复杂基础设施问题，并创建文档化工作流，让技术与非技术团队成员都能独立访问和操纵数据。

**主要用例**：
- **用截图做 Kubernetes 调试**：当 Kubernetes 集群宕机且不再调度新 Pod 时，团队用 Claude Code 诊断问题。他们把仪表盘截图喂给 Claude Code，它引导他们逐菜单穿过 Google Cloud UI，直到找到指示 Pod IP 地址耗尽的警告。Claude Code 随后提供创建新 IP 池并加入集群的确切命令，省去了请网络专家介入。
- **给财务团队的纯文本工作流**：团队教财务成员写描述数据工作流的纯文本文件，然后加载进 Claude Code 获得全自动执行。没有编码经验的员工能描述"查询这个仪表盘、获取信息、运行这些查询、生成 Excel 输出"这样的步骤，Claude Code 会执行整个工作流，包括询问日期等所需输入。
- **新人的代码库导航**：新数据科学家加入时，被指引用 Claude Code 导航庞大的代码库。Claude Code 读取他们的 Claude.md 文件（文档）、为特定任务识别相关文件、解释数据管线依赖、帮新人理解哪些上游源喂给仪表盘。这取代了传统数据目录和发现工具。
- **会话结束时的文档更新**：团队在每个任务结束时请 Claude Code 总结完成的工作会话并建议改进。这创造了持续改进循环——Claude Code 基于实际使用帮助精炼 Claude.md 文档和工作流指令，让后续迭代更有效。
- **跨多实例的并行任务管理**：处理长期数据任务时，他们为不同项目在不同仓库打开多个 Claude Code 实例。每个实例维持完整上下文，所以数小时或数天后切换回来，Claude Code 仍记得他们在做什么、停在哪，实现无上下文丢失的真正并行工作流管理。

**团队影响**：无需专门专长解决基础设施问题（解决了通常要请系统或网络团队成员的 Kubernetes 集群问题）；加速入职（新数据分析师能快速理解复杂系统并无缝贡献）；增强支持工作流（能处理远超人类手动审查能力的数据量，如监控 200 个仪表盘）；实现跨团队自助（无编码经验的财务团队现在能独立执行复杂数据工作流）。

**要点提示**：写详细的 Claude.md 文件（文档得越好，Claude Code 表现越好）；对敏感数据用 MCP 服务器而非 CLI（他们建议用 MCP 服务器而非 BigQuery CLI，以对 Claude Code 能访问什么保持更好安全控制，尤其处理需日志或潜在隐私问题的敏感数据时）；分享团队使用会话（成员互相演示工作流，传播最佳实践）。

## 产品开发团队用 Claude Code

**团队简介**：Claude Code 团队用自己的产品构建 Claude Code 的更新，扩展产品的企业能力和智能体循环功能。

**主要用例**：
- **用自动接受模式快速原型**：工程师启用"自动接受模式"（shift+tab）并搭建自主循环（Claude 写代码、跑测试、持续迭代）来快速原型。他们给 Claude 自己不熟悉的抽象问题，让它自主工作，然后审阅约 80% 完成的方案，再接手做最终精炼。团队强调从干净 git 状态开始、定期提交检查点，以便 Claude 跑偏时容易回滚错误变更。
- **核心特性的同步编码**：对触及应用业务逻辑的更关键特性，团队与 Claude Code 同步工作，给出含具体实现指令的详细提示词。他们实时监控过程以确保代码质量、风格指南合规和架构正确，同时让 Claude 处理重复编码工作。
- **构建 Vim 模式**：他们最成功的异步项目之一是为 Claude Code 实现 Vim 键位绑定。他们让 Claude 构建整个特性（尽管它不是优先级），最终实现约 70% 来自 Claude 的自主工作，仅需几次迭代完成。
- **测试生成与 bug 修复**：实现特性后，他们用 Claude Code 写全面测试，并处理 PR 评审中发现的简单 bug 修复。他们还利用 GitHub Actions 集成让 Claude 自动处理 PR 评论，如格式问题或函数重命名。
- **代码库探索**：面对陌生代码库（如 monorepo 或 API 侧）时，团队用 Claude Code 快速理解系统如何运作。与其等 Slack 回复，他们直接问 Claude 要解释和代码引用，大幅节省上下文切换时间。

**团队影响**：更快实现特性（Vim 模式等复杂特性约 70% 代码由 Claude 自主编写）；提升开发速度（快速原型特性、迭代想法，不被实现细节拖累）；通过自动化测试提升代码质量；更好的代码库探索。

**要点提示**：创建自给自足循环（让 Claude 通过自动运行构建、测试和 lint 验证自己的工作）；培养任务分类直觉（区分适合异步的任务——外围特性、原型，与需要同步监督的任务——核心业务逻辑、关键修复；产品边缘的抽象任务可用自动接受模式，核心功能需更密切监督）；形成清晰详细的提示词（组件名或功能相似时，请求要极其具体）。

## 安全工程团队用 Claude Code

**团队简介**：安全工程团队聚焦保护软件开发生命周期、供应链安全和开发环境安全。他们大量用 Claude Code 编写和调试代码。

**主要用例**：
- **复杂基础设施调试**：处理事件时，他们把堆栈追踪和文档喂给 Claude Code，请它追踪代码库中的控制流。这显著缩短生产问题的解决时间——本来要花 10-15 分钟手动扫代码的问题，约 5 分钟就能理解。
- **Terraform 代码审查与分析**：对需安全审批的基础设施变更，他们把 Terraform plan 复制进 Claude Code 问"这会做什么？我会后悔吗？"。这创造更紧密的反馈循环，让安全团队更快审查和批准基础设施变更，减少开发流程中的瓶颈。
- **文档综合与 runbook**：他们让 Claude Code 摄入多个文档源，创建 markdown runbook、排障指南和概览。用这些浓缩文档作调试真实问题的上下文，比搜索完整知识库更高效。
- **测试驱动开发工作流**：取代此前"设计文档 → 粗糙代码 → 重构 → 放弃测试"的模式，他们现在请 Claude Code 给伪代码、引导它走 TDD，并定期检查在卡住时引导它，产出更可靠、可测试的代码。
- **上下文切换与项目入职**：为现有项目（如"dependant"，一个安全审批工作流的 Web 应用）做贡献时，他们用 Claude Code 编写、审查和执行以 markdown 存储在代码库中的规格，数天内就能有意义贡献（而非数周）。

**团队影响**：缩短事件解决时间（基础设施调试从 10-15 分钟降至约 5 分钟）；改善安全审查周期；增强跨职能贡献；更好的文档工作流。

**要点提示**：广泛使用自定义斜杠命令（安全工程用掉了整个 monorepo 中全部自定义斜杠命令实现的 50%）；让 Claude 先说（告诉它"边做边提交"、自主工作、定期检查，得到更全面方案）；用它做文档（Claude Code 擅长综合文档和创建结构化输出，提供写作样例和格式偏好即可得到能直接用于 Slack、Google Docs 等的文档）。

## 推理团队用 Claude Code

**团队简介**：推理团队管理记忆系统——存储 Claude 读取你的提示词并生成响应时信息的地方。团队成员，尤其刚入机器学习的人，可大量用 Claude Code 弥合知识差距、加速工作。

**主要用例**：
- **代码库理解与入职**：加入复杂代码库时，团队高度依赖 Claude Code 快速理解架构。不用手动搜 GitHub 仓库，他们请 Claude 找哪些文件调用特定功能，几秒得到结果，而非问同事或手动搜索。
- **带边缘情况的单元测试生成**：写完核心功能后，他们请 Claude 写全面单元测试。Claude 自动包含被遗漏的边缘情况，把通常要大量脑力的事几分钟做完，像可审阅的编码助手。
- **机器学习概念讲解**：没有 ML 背景的成员依赖 Claude 解释模型特定函数和设置。本需一小时 Google 搜索和读文档的，现在 10-20 分钟完成，研究时间减少 80%。
- **跨语言代码翻译**：在不同编程语言测试功能时，他们描述想测什么，Claude 用所需语言（如 Rust）写逻辑，省去为测试学新语言。
- **命令记忆与 Kubernetes 管理**：不用记复杂 Kubernetes 命令，他们问 Claude 正确语法，如"怎么获取所有 pod 或部署状态"，立刻得到基础设施工作所需的确切命令。

**团队影响**：加速 ML 概念学习（研究时间减少 80%）；更快代码库导航；全面测试覆盖；消除语言障碍。

**要点提示**：先测试知识库功能（问各种问题看 Claude 是否比 Google 搜索更快；若更快更准，就是省时工具）；从代码生成开始（给具体指令让它写逻辑，再验证正确性，先建立信任再用更复杂任务）；用它写测试（缓解日常开发压力）。

## 数据科学与可视化团队用 Claude Code

**团队简介**：数据科学与 ML 工程团队需要精密可视化工具理解模型表现，但构建这些工具常需陌生语言和框架的专长。Claude Code 让这些团队无需成为全栈开发者就能构建生产质量的分析仪表盘。

**主要用例**：
- **构建 JavaScript/TypeScript 仪表盘应用**：尽管"几乎不懂 JavaScript 和 TypeScript"，团队用 Claude Code 构建整个 React 应用来可视化 RL 模型表现和训练数据。他们让 Claude 从头写完整应用（如 5000 行 TypeScript 应用），自己无需理解代码。这很关键，因为可视化应用上下文相对低，无需理解整个 monorepo，允许快速原型工具以理解训练和评估期间的模型表现。
- **处理重复重构任务**：面对合并冲突、或"对编辑器宏太复杂但对大开发投入又不够"的半复杂文件重构时，他们把 Claude Code 当"老虎机"——提交状态、让 Claude 自主工作 30 分钟，接受方案或不行就重来。
- **创建持久分析工具而非一次性笔记本**：不再构建被丢弃的一次性 Jupyter notebook，团队现在让 Claude 构建可跨未来模型评估复用的持久 React 仪表盘。这很重要，因为理解 Claude 的表现"对团队是最重要的事之一"——他们需要理解训练和评估期间模型如何表现，而"这实际并不平凡，简单工具无法只看单个数字上升就得到多少信号"。
- **零依赖任务委派**：对完全陌生代码库或语言的任务，他们把整个实现委派给 Claude Code，利用它从 monorepo 收集上下文并执行任务的能力，自己无需卷入实际编码过程。这让在专长之外的领域保持生产力，而非花时间学新技术。

**团队影响**：实现 2-4 倍时间节省；在陌生语言中构建复杂应用（用最少 JS/TS 经验创建 5000 行 TypeScript 应用）；从一次性转向持久工具；直接模型改进洞察；实现可视化驱动的决策。

**要点提示**：当老虎机用（让 Claude 工作前保存状态，跑 30 分钟，接受或重来——重来常比修正 Claude 错误成功率更高）；需要时打断要简单（监督时别犹豫停下问"为什么这么做？试个更简单的"，模型默认偏向复杂方案，但对简单化请求响应良好）。

## API 团队用 Claude Code

**团队简介**：API Knowledge 团队做 PDF 支持、引用和 Web 搜索等功能——把额外知识带进 Claude 上下文窗口。跨大型复杂代码库工作意味着不断遇到陌生代码段、花大量时间理解任何给定任务该查哪些文件、以及在做变更前构建上下文。Claude Code 通过担任指南（帮理解系统架构、识别相关文件、解释复杂交互）改善这种体验。

**主要用例**：
- **第一步工作流规划**：团队把 Claude Code 当任何任务的"第一站"，请它识别该查哪些文件做 bug 修复、特性开发或分析。这取代了传统上"手动导航代码库、开工前收集上下文"的耗时流程。
- **跨代码库独立调试**：团队现在有自信处理陌生代码库部分的 bug，而不再求人。他们能问 Claude"你觉得你能修这个 bug 吗？这是我看到的行为"，常立刻有进展——这在以前因所需时间投入是不可行的。
- **通过 dogfooding 做模型迭代测试**：Claude Code 自动用最新研究模型快照，是他们体验模型变化的主要方式。这让他们在开发周期中直接反馈模型行为变化。
- **消除上下文切换开销**：不再复制代码片段、拖文件进 Claude.ai 并大量解释问题，他们能直接在 Claude Code 里问问题，无需额外收集上下文，显著减少脑力开销。

**团队影响**：增强处理陌生领域的自信；收集上下文显著省时；更快轮岗入职；提升开发者幸福感（团队报告日常摩擦减少，更快乐更高效）。

**要点提示**：把它当迭代伙伴而非一次性方案；用它建立陌生领域的自信；从最少信息开始（只给最低限度，让 Claude 引导，而非前置大量解释）。

## 增长营销团队用 Claude Code

**团队简介**：增长营销团队聚焦建立付费搜索、付费社交、移动应用商店、邮件营销和 SEO 的绩效营销渠道。作为单人的非技术团队，他们用 Claude Code 自动化重复营销任务、创建传统上需要大量工程资源的智能体工作流。

**主要用例**：
- **自动化 Google Ads 创意生成**：团队构建了一个智能体工作流，处理含数百个现有广告及表现指标的 CSV 文件、识别表现不佳的广告迭代、生成满足严格字符限制（标题 30 字符、描述 90 字符）的新变体。用两个专门子智能体（一个管标题、一个管描述），系统能在几分钟生成数百个新广告，而非跨多营销活动手动创建。
- **Figma 插件做批量创意生产**：不再手动复制和编辑付费社交广告的静态图，他们开发了 Figma 插件，识别帧并程序化地通过替换标题和描述生成最多 100 个广告变体，把本要数小时复制粘贴的事降到每批半秒。这实现 10 倍创意产出。
- **Meta Ads MCP 服务器做营销活动分析**：他们创建了与 Meta Ads API 集成的 MCP 服务器，在 Claude Desktop 应用内直接查询营销活动表现、花费数据和广告效果，省去跨平台切换做表现分析的时间。
- **带记忆系统的进阶提示词工程**：他们实现了基础记忆系统，跨广告迭代记录假设和实验，让系统生成新变体时能把先前测试结果拉进上下文，创造自我改进的测试框架。

**团队影响**：重复任务大幅省时（广告文案创建从 2 小时降到 15 分钟）；创意产出 10 倍提升；像更大团队一样运作；战略焦点转移。

**要点提示**：识别有 API 的重复任务（找涉及重复动作、工具有 API 的工作流——广告平台、设计工具、分析平台，这些是自动化的最佳候选）；把复杂工作流拆成专门子智能体（如他们的标题智能体 vs 描述智能体，更易调试、提升复杂需求下的输出质量）；编码前充分头脑风暴和规划提示词（用 Claude.ai 想透整个工作流，再让 Claude.ai 创建供 Claude Code 参考的全面提示词和代码结构；分步工作而非一次性方案）。

## 产品设计团队用 Claude Code

**团队简介**：产品设计团队支持 Claude Code、Claude.ai 和 Anthropic API，专长构建 AI 产品。甚至非开发者都能用 Claude Code 弥合设计与工程的传统鸿沟，无需与工程师大量来回就能直接实现其设计愿景。

**主要用例**：
- **前端打磨与状态管理变更**：不再创建设计文档并和工程师多轮反馈视觉微调（字体、颜色、间距），他们现在直接用 Claude Code 实现这些变更。工程师指出他们在做"你通常不会看到设计师做的大的状态管理变更"，能达成他们设想的精确质量。
- **GitHub Actions 自动化工单**：用 Claude Code 的 GitHub 集成，他们直接提 issue/工单描述所需变更，Claude 自动提议代码方案而无需打开 Claude Code，为持久打磨任务积压清单创造无缝的 bug 修复与特性精炼工作流。
- **快速交互原型**：把 mockup 图粘贴进 Claude Code，他们生成工程师能立即理解和迭代的完全可用原型，取代传统"静态 Figma 设计需大量解释和翻译成可工作代码"的循环。
- **边缘情况发现与系统架构理解**：他们用 Claude Code 梳理错误状态、逻辑流和不同系统状态，在设计期识别边缘情况而非开发后期发现，从根本上提升初始设计质量。
- **复杂文案变更与法务合规**：对如"移除整个代码库中的 research preview 字样"这类任务，他们用 Claude Code 找所有实例、审阅周边文案、与法务实时协调、并实现更新——这个过程只花两个 30 分钟通话，而非一周的来回协调。

**团队影响**：转变核心工作流（Claude Code 成为主要设计工具，Figma 和 Claude Code 80% 时间开着）；执行快 2-3 倍；周期从数周缩到数小时；两种截然不同的用户体验（开发者获得"增强工作流"，非技术用户获得全新的、此前不可能的能力）；改善设计-工程协作。

**要点提示**：让工程师帮做初始仓库设置和权限（对非开发者技术入职有挑战，配置好后变革日常工作流）；用自定义记忆文件引导 Claude 行为（创建具体指令说明"你是编码经验少的设计师、需要详细解释和更小增量变更"）；利用图片粘贴做原型（Command+V 直接粘贴截图进 Claude Code，它擅长读设计和生成可用代码）。

## RL 工程团队用 Claude Code

**团队简介**：RL 工程团队聚焦 RL 中的高效采样和跨集群的权重传输。他们主要用 Claude Code 写中小型特性、调试和理解复杂代码库，采用含频繁检查点与回滚的迭代方法。

**主要用例**：
- **带监督自主的特性开发**：团队让 Claude Code 写中小型特性的大部分代码同时提供监督，如为权重传输组件实现认证机制。他们交互式工作，让 Claude 牵头但在跑偏时引导。
- **测试生成与代码审查**：自己实现变更后，他们请 Claude Code 加测试或审查代码。这个自动化测试工作流为常规但重要的 QA 任务节省大量时间。
- **调试与错误调查**：他们用 Claude Code 调试错误，结果好坏参半——有时立刻识别问题并加相关测试，有时难以理解问题，但总体有效时有价值。
- **代码库理解与调用栈分析**：工作流最大的变化之一是：用 Claude Code 快速总结相关组件和调用栈，取代手动读代码或生成大量调试输出。
- **Kubernetes 运维指导**：他们常问 Claude Code Kubernetes 运维问题（否则要大量 Google），即时获得配置和部署问题答案。

**工作流影响**：启用实验方法（用"试了再回滚"方法论，频繁提交检查点）；文档加速（Claude Code 自动加有用注释，虽有时位置奇怪或用可疑代码组织）；有局限的加速（它"相对少时间"实现中小 PR，但承认约三分之一时间首次尝试就能成，其余需额外指导或人工干预）。

**要点提示**：针对特定模式定制 Claude.md 文件（加指令防止 Claude 重复犯工具调用错误，如告诉它"run pytest not run，别不必要 cd——直接用对路径"）；用检查点密集工作流；先试一次性方案再协作（先给快速提示让它尝试完整实现，成了省大量时间，不成再切到协作引导式方法）。

## 法律团队用 Claude Code

**团队简介**：法律团队通过实验和对 Anthropic 产品了解的兴趣发现 Claude Code 的潜力。此外，一名成员有与为家人和工作原型创建无障碍工具相关的个人用例，展示了该技术对非开发者的力量。

**主要用例**：
- **为家人的自定义无障碍方案**：成员为因医疗诊断有言语困难的家人构建了沟通助手。只用一小时，他们用原生语音转文本创建了预测文本应用——建议回应并用语音库说出来，解决了言语治疗师推荐的无障碍工具中的空白。
- **法务部门工作流自动化**：他们创建了原型"电话树"系统，帮成员联系 Anthropic 正确的律师，展示法务部门无需传统开发资源就能为常见任务构建自定义工具。
- **团队协调工具**：管理者构建了自动化每周团队更新、跨产品追踪法律审查状态的 G Suite 应用，让律师通过简单点按钮快速标记需审查项，而非电子表格管理。
- **方案验证的快速原型**：他们用 Claude Code 快速构建可用原型给领域专家看（如给 UCSF 专家看无障碍工具），在投入更多时间前验证想法、识别现有方案。

**工作风格与影响**：在 Claude.ai 规划、在 Claude Code 构建（先用 Claude.ai 头脑风暴和规划，再切到 Claude Code 实现，请它放慢、分步工作而非一次输出全部）；视觉优先方法（常用截图展示想要的界面，基于视觉反馈迭代而非文本描述特性）；原型驱动创新（强调克服分享"傻"或"玩具"原型的恐惧，这些演示激励他人看到没想到的可能性）。

**安全与合规意识**：MCP 集成顾虑（作为产品律师，他们立即识别深度 MCP 集成的安全隐患，指出保守的安全姿态会随 AI 工具访问更敏感系统而制造障碍）；合规工具优先级（主张随 AI 能力扩展快速构建合规工具，认识到创新与风险管理间的平衡）。

**要点提示**：先在 Claude.ai 大量规划（用对话界面完善整个想法，再让 Claude 总结成逐步实现提示词）；增量且可视化地工作（请 Claude Code 放慢、一次实现一步，以便复制粘贴不被淹没；大量用截图展示想要的界面）；分享不完美的原型（克服隐藏"玩具"项目或未完成工作的冲动）。
